# Guidance Trajectory 생성 방법 개선 보고서

## 1. 개요

```
 costmap + dynamic obstacles
          │
          ▼
   StepMapBuilder::update()
          │
          ▼
      StepMap (x, y, t)          ← 3D 시공간 점유 그리드
          │
    ┌─────┴──────────────────────────────┐
    │ 현재: Visibility-PRM               │
    │   랜덤 샘플링 → 이진 충돌 판정      │
    │   → Guard/Connector → DFS 탐색     │
    └──────────────┬─────────────────────┘
                   │  ← 구조적 비효율 (§2)
                   ▼
    ┌──────────────────────────────────────┐
    │ 개선: Grid-Based DAG-DP              │
    │   그리드 전체 탐색 → 연속 비용 활용   │
    │   → 층별 DP → 호모토피별 최적 경로   │
    └──────────────┬───────────────────────┘
                   │
                   ▼
        guidance trajectories
     (위상 구별, 동역학 일관, 결정적)
                   │
                   ▼
          MPC trajectory optimization
                   │
                   ▼
               /cmd_vel
```

T-MPC++의 guidance planner는 StepMap을 기반으로 위상적으로 구별되는 복수의 guidance trajectory를 생성한다. 현재 방식(Visibility-PRM)의 구조적 비효율을 해소하고 StepMap의 잠재력을 충분히 활용하기 위해 **그리드 기반 DAG-DP** 방식으로 전환한다.

---

## 2. Sampling → Grid 전환 이유

현재 Visibility-PRM은 StepMap 위에서 랜덤 샘플링으로 노드를 생성하고, 각 노드의 충돌 여부를 StepMap에 질의한다. 이 구조에는 세 가지 근본적 비효율이 있다.

**비효율 1 — 이미 완성된 그리드 위에서 랜덤 탐색**
StepMap은 100×100×20 = 200,000개 셀의 점유 정보를 이미 완전히 갖고 있다. PRM은 그 중 50개를 랜덤 샘플링하여 0.025%만 본다.

**비효율 2 — 연속 비용값 완전 폐기**
`cellCost()`는 0.0~1.0의 연속 비용을 반환하지만, PRM 파이프라인의 세 호출 지점 모두 `occupancy_threshold(0.4)` 기준의 이진 판정만 수행한다. 가우시안 샘플링이 만들어낸 "장애물 확률 필드"가 전혀 활용되지 않는다.

**비효율 3 — 확률적 완전성의 한계**
실시간 제약(timeout=10ms) 내에서 좁은 통로를 놓치거나, 같은 입력에서 매번 다른 결과가 나올 수 있다.

**그리드 기반 탐색의 이점:**
- Resolution-complete: 좁은 통로를 놓치지 않음
- 결정적: 같은 입력 → 같은 출력
- `cellCost` 연속값을 에지 비용으로 직접 활용
- 시간 축의 DAG 구조를 이용해 우선순위 큐 없이 O(V) 탐색 가능

## 3. 대안 알고리즘 비교

| 방법 | 핵심 아이디어 | 토폴로지 보장 | 속도 | 구현 복잡도 | 주요 단점 |
|------|-------------|:---:|:---:|:---:|---------|
| **A. Winding-Angle A\*** | 상태에 winding label 추가, A\* 탐색 | ✓ (수학적) | 중간 (10-20ms) | 중간 | 장애물 수 M에 지수적 상태 공간 (2^M) |
| **B. Distance-Field Corridor** | 거리 변환 → GVD 골격 추출 → 회랑별 탐색 | 미보장 | 빠름 (1-3ms) | 높음 | 노이즈·개방 공간에서 골격 불안정 |
| **C. Penalty-Based Iterative** | 최적 경로 탐색 → 경로 주변 벌점 → 반복 | 미보장 | 빠름 (3-8ms) | 낮음 | 파라미터 튜닝 필요, 순차 의존성 |
| **D. DAG-DP** *(채택)* | 시간 층 순차 DP, winding label 상태 확장 | ✓ (호모토피별 최적) | 빠름 | 중간 | 상태 공간 크기 (그리드 × label 수) |

---

## 4. DAG-DP 채택 이유

시공간 그리드에서 시간 축은 단방향이므로 그래프가 자연스럽게 DAG를 이룬다. 이 구조가 두 가지 강점을 제공한다:

1. **DP 최적성 보장**: 시간 층 순서대로 처리하면 각 호모토피 클래스 내 최적 경로가 보장된다.
2. **우선순위 큐 불필요**: Dijkstra의 O(V log V) 대신 O(V) 층별 순회로 동작한다.

여기에 동역학 제약(속도·각속도 한계)을 전이 규칙에 내재화하면, MPC가 실제로 추종 가능한 경로만 생성할 수 있다.

## 5. DAG-DP 핵심 알고리즘

### 5.1 이산화된 Heading Bin

로봇은 전진만 가능하므로 heading은 **전방 반원([-90°, +90°])** 만 커버하면 된다. 이를 22.5° 간격으로 8등분한다.

```
          StepMap 로컬 좌표 (X = 로봇 전진 방향)

               bin2  bin3  bin4  bin5  bin6
              -45°  -22°   0°  +22°  +45°
                 \    |    |    |    /
          bin1   \   |    |    |   /   bin7
         -67°    \  |    ↑    |  /   +67°
                  \ |    │    | /
    bin0 ─────────── ★ ──────────── (전진)   bin8 는 없음
         -90°                           +90°
                  / |         | \
                 /  └── ★ = 현재 위치

  bin 0: -90.0°  bin 1: -67.5°  bin 2: -45.0°  bin 3: -22.5°
  bin 4:   0.0°  bin 5: +22.5°  bin 6: +45.0°  bin 7: +90.0°

  STATIONARY(8): 시작점에서만, 제자리 대기
```

### 5.2 전이 범위 — 부채꼴

한 시간 스텝에서 이동할 수 있는 셀의 범위는 두 조건의 교집합이다.

```
  조건 1 (속도 제한):   spatial_dist ≤ v_max × dt = 0.6 m
  조건 2 (각속도 제한): |Δθ| ≤ ω_max × dt ≈ 34.4°

  현재 heading = bin4 (0°, 정면)  /  resolution = 0.2m

          거리 제한 (반경 3셀) 내 모든 셀:

              · · · · · · ·
            · · · · · · · · ·
          · · · · · · · · · · ·
          · · · · · · · · · · ·
          · · · · ★ · · · · · ·     ← 현재 위치
          · · · · · · · · · · ·
              · · · · · · ·

          각속도 제약 (±34.4°) 적용 후 도달 가능 셀:

                  ▲ (전진 방향)
              / ✓ ✓ ✓ \
            / ✓ ✓ ✓ ✓ ✓ \
          /  ✓ ✓ ✓ ✓ ✓ ✓ \
          ·  ·  ·  ★  ·  ·  ·      ★ = 현재 위치
          ·  ·  ·  ·  ·  ·  ·      ✓ = 도달 가능
          ·  ·  ·  ·  ·  ·  ·      · = 거리·각도 제한으로 불가

          → 전방 부채꼴 (±34.4° 범위, 반경 3셀)
          → 약 8~12개 이웃 셀 (전체 28셀의 ~35%)
```

### 5.3 상태 정의

```
State = (gx, gy, gt, θ_bin, h)

- (gx, gy) : 그리드 셀 좌표
- gt        : 시간 층 (0 ~ N-1)
- θ_bin     : 이산화된 heading (22.5° 간격, 전방 반원 8개 bin)
- h         : winding label (uint64_t, 장애물별 2비트: LEFT/RIGHT/UNDECIDED)
```

### 5.4 전이 조건 (동역학 제약 내재화)

셀 `(gx, gy, gt, θ_prev)` → `(gx', gy', gt+1, θ_next)` 전이 허용 조건:

```
1. 그리드 범위 내
2. cellCost(gx', gy', gt+1) < hard_threshold   (소프트 비용 필드 활용)
3. spatial_dist ≤ v_max × dt                    (속도 제한: 0.6 m/step)
4. |Δθ| ≤ ω_max × dt                           (각속도 제한: 0.6 rad/step)
5. 또는 (dx=0, dy=0)                            (제자리 대기 허용)

* 후진 방지: θ_bin 범위를 전방 반원 [-π/2, +π/2]로 제한하여 내재화
```

### 5.5 에지 비용

```
edge_cost = w_dist × C_dist + w_obs × C_obs + w_smooth × C_smooth + w_progress × C_progress

C_dist     = sqrt(dx²+dy²) × resolution               (이동 거리)
C_obs      = exp(γ × cellCost(gx', gy', gt+1)) - 1.0  (장애물 반발, 연속 비용 활용)
C_smooth   = (Δθ / Δψ_max)²                           (방향 변화 페널티)
C_progress = -progress_along_reference(gx', gy')       (참조 경로 진행 보상)
```

`C_obs`는 `cellCost`를 지수 함수로 변환하여, 비용이 낮은 영역도 자연스럽게 회피한다.

### 5.6 전체 흐름

```
  입력: StepMap, obstacles[], start_pos, start_heading, reference_path, n_paths

  ┌─────────────────────────────────────────────────────────────────┐
  │ Phase 1 — 전처리                                                 │
  │   heading별 도달 가능 이웃 테이블 사전 계산 (1회)                  │
  │   (동역학 파라미터 고정 시 캐싱 가능)                              │
  └──────────────────────────┬──────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ Phase 2 — 층별 전진 전파 (슬라이딩 윈도우 DP)                     │
  │                                                                 │
  │   gt=0   gt=1   gt=2   gt=3   ...   gt=N-1                     │
  │  ┌───┐  ┌───┐  ┌───┐  ┌───┐        ┌───┐                      │
  │  │ S │─▶│   │─▶│   │─▶│   │──···──▶│ G?│                      │
  │  └───┘  └───┘  └───┘  └───┘        └───┘                      │
  │  curr → next  (2-층 슬라이딩 윈도우)                              │
  │                                                                 │
  │  각 셀: (gx, gy, θ_bin, h) 상태별 최솟값 갱신                    │
  │  h 갱신: 장애물을 왼쪽/오른쪽으로 지날 때 winding label 변경       │
  └──────────────────────────┬──────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ Phase 3 — 경로 수집                                              │
  │   목표 영역의 셀에서 winding label(h)별 최적 경로 역추적            │
  │   → 서로 다른 h = 서로 다른 토폴로지 경로                          │
  └──────────────────────────┬──────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ Phase 4 — 품질 평가 및 필터링                                     │
  │   score = α×total_progress + β×(-total_cost) + γ×(-max_curv)   │
  │   진행 미달 / 품질 미달 경로 제거 → 상위 n_paths개 선택            │
  └──────────────────────────┬──────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │ Phase 5 — 경로 변환                                              │
  │   셀 시퀀스 → 월드 좌표 → 스무딩 → GeometricPath → CubicSpline3D │
  └─────────────────────────────────────────────────────────────────┘

  출력: vector<GeometricPath>  (0 ~ n_paths개, 호모토피별 최적)
```

### 5.7 메모리 구조 (슬라이딩 윈도우)

전체 그리드를 저장하는 대신 `curr_layer / next_layer` 두 층만 유지한다. 역추적용 predecessor는 `cells_t` 개의 해시맵으로 별도 저장한다.

## 6. 기대 효과

| 항목 | 현재 (Visibility-PRM) | 개선 (DAG-DP) |
|------|----------------------|--------------|
| cellCost 활용 | 이진 판정만 | 연속 에지 비용으로 활용 |
| 재현성 | 확률적 | 결정적 |
| 좁은 통로 | 놓칠 수 있음 | Resolution-complete |
| 동역학 일관성 | 없음 | 전이 규칙에 내재화 |
| 탐색 복잡도 | O(V log V) + 재샘플링 | O(V) 층별 순회 |
| 호모토피 최적성 | 샘플 의존 | 각 클래스 내 보장 |
